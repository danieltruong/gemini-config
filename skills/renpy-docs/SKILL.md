# Ren'Py documentation lookup

The mirror is Ren'Py 8.5.4, fetched 2026-09-18, at `F:\Factory\renpy\docs\renpy\`.

## How to look something up

1. Known symbol (function, class, action, config variable, style property, text tag): grep
   `docs/renpy/symbols.tsv` for the name. Columns are name, kind, file. Open the file it names
   and search for the name there.
2. Topic or statement: read `docs/renpy/INDEX.md`. It lists every page with a title, a
   one-sentence summary and its headings. Open the matching page.
3. Nothing matches: grep the text of `docs/renpy/*.md`.

Say so when the mirror does not cover something, instead of guessing.

Never edit files under `docs/renpy/`. They are generated by
`python .agents/scripts/fetch-docs.py --site renpy`, run from `F:\Factory\renpy`.

## Text interpolation

Two facts that get argued about.

From `text.md`, "Interpolating Data":

- A format spec after a colon works: `[value:.1f]`. Ren'Py takes PEP 3101 syntax and passes the
  spec to Python `format()`, so `[100.0 * points / max_points:.2]` prints a rounded number.
- Conversion flags: `!s` and `!r` as in Python, plus `!q` quotes text tags, `!t` translates,
  `!i` interpolates again, `!u` uppercases, `!l` lowercases, `!c` capitalizes the first
  character only. Combine them for the rest: `!cl` capitalizes the first character and
  lowercases the remainder.

Inferred from the engine source, not stated in the mirror: in `convert()` in
`renpy/substitutions.py`, any of the flags `t i q u l c` coerces the value to `str` before
`format()` runs. So one of those flags combined with a numeric format spec fails.
